# Как предложить изменение

Спасибо, что хотите помочь! Сообщения об ошибках особенно полезны.

## Перед PR

- **Сначала issue.** Опишите проблему или идею в issue и сошлитесь на него из PR.
- **Новые инструменты, команды и всё, что меняет безопасность** (что и когда отправляется, токен, привязка, проверка файлов), — только после обсуждения в issue.
- **Всё — через pull request** в `main`, с зелёным CI.

## Настройка

```bash
npm test          # тесты, как в CI
npm run validate  # строгая проверка манифестов (нужен `claude` в PATH)
```

Запуск плагина из рабочей копии и проверка на тестовом боте — [docs/development.md](docs/development.md). Правила кода — [AGENTS.md](AGENTS.md).

## Что проверяет CI

На каждый PR и push в `main`: тесты на Ubuntu и Windows с Node 22 и 24, строгая проверка манифестов плагина и marketplace.

Заголовок PR и коммиты — conventional commits по смыслу: `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `ci:`, `chore:`.

## Уязвимости

Не публикуйте их в открытых issue — см. [SECURITY.md](SECURITY.md).
