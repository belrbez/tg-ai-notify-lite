# Правила для агентов и разработчиков

Этот репозиторий — плагин Claude Code `tg-ai-notify-lite` и его собственный marketplace. Корень репозитория — корень плагина.

`AGENTS.md` — главный файл правил. Claude Code читает его через `.claude/CLAUDE.md` (там только `@../AGENTS.md`). **Не кладите `CLAUDE.md` в корень:** корень — это корень плагина, и `claude plugin validate --strict` на нём падает («CLAUDE.md at the plugin root is not loaded as project context»).

## Быстрый старт

```bash
npm test              # все тесты, так же, как в CI
npm run validate      # строгая проверка манифестов плагина и marketplace (нужен `claude` в PATH)
npm run check         # тесты + проверка — перед каждым PR
```

Зависимостей нет: только Node.js 22+ (встроенные `fetch`, `node:test`). Не добавляйте npm-зависимости без обсуждения.

Как запустить плагин из рабочей копии, проверить на тестовом боте и отладить сервер — [docs/development.md](docs/development.md).

## Рабочие договорённости

- **Ветки и PR.** Любое нетривиальное изменение — в отдельной ветке; в `main` только через pull request с зелёным CI. Прямых коммитов в `main` нет.
- **Коммиты и заголовки PR** — conventional commits по смыслу изменения: `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `ci:`, `chore:`. Файлы в `skills/` и `commands/` — продуктовый код, хотя это Markdown.
- **Версия.** Меняется вместе в `.claude-plugin/plugin.json`, `package.json`, `server/main.mjs` (`VERSION`) и `server/index.mjs` (`serverInfo.version`); тест `test/repo.test.mjs` проверяет совпадение. Запись в [CHANGELOG.md](CHANGELOG.md) — в том же PR. Без новой версии пользователи не получат изменения: `/plugin update` сравнивает версии.
- **Тесты.** После изменения кода, скилла, команды или манифеста запускайте `npm run check`. Новая логика — с тестом; исправление ошибки — сначала падающий тест. Тесты работают с поддельным Telegram API (`test/fake-telegram.mjs`), без сети и без настоящего бота.
- **PR.** Заполняйте разделы «Безопасность» и «Агент» из `.github/pull_request_template.md`, даже если PR создаётся через `gh pr create --body`.

## Правила безопасности (не ослаблять без явного решения автора)

- Плагин **ничего не отправляет по собственной инициативе** — только по явной просьбе пользователя или в заданной им задаче (`basis`).
- **Токен бота** никогда не попадает в ответы инструментов, ошибки, журнал и stderr — всё проходит через редактор токена (`server/lib/secrets.mjs`). Токен не принимается и не запрашивается через чат — только страница настройки (`server/lib/setup-page.mjs`) или `/plugin`.
- **Привязка чата** сохраняется только по 6-значному коду, который бот прислал в этот чат. Код живёт только в памяти процесса — не пишите его на диск и не возвращайте в ответах инструментов.
- **Файлы**: проверки в `server/lib/files.mjs` (секретные имена и папки, UNC, потоки NTFS, жёсткие ссылки, содержимое) — только расширять.
- Подмена адреса Telegram API — только для тестов: `TGN_TEST_MODE=1` и локальный адрес.
- Любое изменение этих правил — отдельным PR с описанием в разделе «Безопасность».

## Стиль

- Код — ES-модули (`.mjs`), без сборки и без TypeScript. `server/index.mjs` пишется на старом синтаксисе (`var`, без `?.`), чтобы старый Node мог его разобрать и объяснить, что нужен Node 22+.
- Комментарии в коде — по-английски, коротко и по делу; тексты для пользователя и модели — по-русски.
- Имена файлов, инструментов, команд — только ASCII.
- Тексты ошибок для пользователя говорят, **что сделать**, а не только что сломалось.

## Структура

```
.claude-plugin/     манифест плагина (plugin.json) и marketplace (marketplace.json)
.claude/CLAUDE.md   подключает этот файл для Claude Code
.github/            CI и шаблон PR
assets/             логотип для README
commands/           команды плагина (/tg-ai-notify-lite:rebind)
skills/telegram/    скилл: когда и как Claude отправляет в Telegram
server/             MCP-сервер (stdio, JSON-RPC без SDK)
  index.mjs         точка входа, проверка версии Node
  main.mjs          протокол MCP, выбор токена, сборка инструментов
  lib/              логика: сообщения, Telegram API, привязка, файлы, состояние, страница настройки
test/               тесты node:test и поддельный Telegram
docs/               чек-лист приёмки, руководство разработчика
```
